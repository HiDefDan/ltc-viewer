## What to set up here

1. **Inspect this host first**: OS/kernel, which NIC will carry PTP + AES67 traffic, and whether that NIC supports **hardware PTP timestamping** (check with `ethtool -T <iface>` — look for `hardware-transmit`/`hardware-receive` and a `/dev/ptp*` device). Use hardware timestamping if available, fall back to software timestamping (`time_stamping software` in `ptp4l.conf`) if not — don't assume the hardware matches the sender's Pi 5.

2. **PTP follower**: install `linuxptp`, configure `ptp4l` on the correct interface with `domainNumber 0` and default priority (don't force priority1 low — this box should never try to become master). Bring it up, then verify with `pmc -u -b 0 'GET PARENT_DATA_SET'` that it has selected the `aes67` box's grandmasterIdentity (`d83add.fffe.bc849b`) as parent, and check `GET CURRENT_DATA_SET` for a converging/near-zero `offsetFromMaster`. Sync the system clock from the PHC with `phc2sys` (opposite direction from the grandmaster: here it should be PHC/PTP → system clock, i.e. `phc2sys -s <iface> -c CLOCK_REALTIME -w` or `-a -r` auto mode) if you need wall-clock accuracy locally, in addition to whatever audio-clock sync PipeWire needs.

3. **AES67 receive via PipeWire**: install `pipewire`, `pipewire-audio`, `wireplumber`. Load `libpipewire-module-rtp-source` with static session parameters matching the stream above (don't rely on SAP): `local.ifname`, `source.ip`/multicast group `239.69.1.1`, `destination.port 5004` (module option names may differ slightly for source vs sink — check `man 7 libpipewire-module-rtp-source` on this box), `sess.media = audio`, and the L24/48000/1 mono format. This creates an `Audio/Source`-class node with the decoded PCM audio available for other PipeWire clients to capture from — unlike `rtp-sink`, `rtp-source` does not need a pre-existing "target" workaround (that gotcha was specific to sending).

4. **LTC decode**: build `x42/ltc-tools` from source against `libltc-dev` + `libjack-jackd2-dev` (same as the sender did) to get `jltcdump` — a real-time JACK/PipeWire LTC decoder. Run it via `pw-jack jltcdump`, then `pw-link` its input port to the `rtp-source` node's output port. Confirm you see correctly incrementing, wall-clock-matching timecode (compare against `date -u` on this box, since the sender generates UTC).

5. **Make it a persistent, boot-resilient service** the same way the sender did: run PipeWire headless via `loginctl enable-linger` + user systemd units (`pipewire.socket`, `pipewire.service`, `wireplumber.service`), and wrap `jltcdump` in its own `Restart=always` unit that re-links to the rtp-source node on every (re)start, since PipeWire nodes for JACK-bridged apps get recreated each launch and won't stay linked across a restart.
